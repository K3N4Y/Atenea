Read a workspace file through `path` and return numbered lines for anchored edits.

<instruction>
- You SHOULD parallelize independent reads.
- Use glob to find files by name and grep to find content; use read once you know which file and range you need.
- Prefer one broad range over many small reads.
</instruction>

<conditions>
- `path` names a local text file inside the workspace.
- Append a supported selector when only part of the file is needed.
- File names containing `:` are not supported because the final colon starts the selector.
</conditions>

## Selectors — append `:<sel>` to `path` (for example `src/foo.go:50-200`)
- `:50` reads line 50; `:50-200` reads an inclusive range. Lines are 1-indexed.
- With no selector, read returns at most 2,000 lines and about 30 KiB from the start of the file.
- A truncated result ends with `[N more lines in file. Use :M to continue]`; re-read using the named selector.

## Output
- Text output starts with a `[path#HASH]` snapshot header followed by `LINE:TEXT` lines.
- Copy the exact `[path#HASH]` header into edit patches. The hash identifies the content you read; NEVER fabricate the hash.
- If the snapshot cannot be retained safely because of a limit or collision, read returns a notice without a header. Change or reduce the content or start a new session, then use read again before editing.
- Files containing NUL bytes are treated as binary and cannot be read or edited through this tool.

<critical>
- A selector exposes only the requested lines. NEVER guess omitted content; read another range when needed.
- Read does not support directories, URLs, archives, databases, documents, images, or internal URIs; use the tool dedicated to that source when available.
</critical>
