Apply a hashline patch to an EXISTING workspace file after reading the exact lines to change. Use `write` to create a new file; edit never creates files.

## Input grammar
- `patch` starts with the exact `[path#HASH]` header returned by the latest read, write, or edit. NEVER invent the hash.
- Follow it with one or more operations using the 1-based inclusive line numbers from that snapshot:
  - `SWAP a.=b:` replaces a range; `SWAP n:` replaces one line.
  - `DEL a.=b` deletes a range; `DEL n` deletes one line. DEL has no colon or payload.
  - `INS.PRE n:` / `INS.POST n:` insert before/after one line.
  - `INS.HEAD:` / `INS.TAIL:` insert at the live start/end.
- Every added payload line begins with `+`; a new blank line is `+` alone.
- Ranges MUST use `.=`. SWAP and INS operations MUST end in `:`; DEL MUST NOT.

## Examples
- Replace lines 12-14 and append one line:
    [internal/foo.go#a1b2]
    SWAP 12.=14:
    +func Foo() error {
    +	return nil
    +}
    INS.TAIL:
    +// end

- Delete one line: `[internal/foo.go#a1b2]\nDEL 7`.

## Recoverable failures
- Unknown/stale hash or ambiguous moved anchors: re-read the current file and rebuild the patch from the new header and line numbers.
- Malformed operation: fix the exact grammar (`.=`, required/forbidden colon, single-line INS anchor, and `+` payload prefixes).
- If a committed change returns sin header because of snapshot limit or colision, do not repeat it: change or reduce the content or start a sesion nueva, then use read before another edit.
- A committed durability warning means the replacement is already visible: never retry that patch; continue from the returned header or re-read.

## Anti-patterns
- WRONG: guess a hash or line number from memory. RIGHT: copy them from the latest visible snapshot.
- WRONG: write `SWAP 12-14` or `DEL 7:`. RIGHT: write `SWAP 12.=14:` or `DEL 7`.
- WRONG: retry an edit reported as committed. RIGHT: continue from its header or re-read.

<critical>
- Read before edit and patch only lines actually shown to you.
- Use the grammar exactly; every payload line starts with `+`.
- On stale anchors re-read; on committed results never retry.
</critical>
