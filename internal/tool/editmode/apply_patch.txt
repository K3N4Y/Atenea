Apply a file-oriented patch containing one or more add, delete, update, or move operations. Paths must be workspace-relative.

## Input grammar
- Wrap the complete patch in `*** Begin Patch` and `*** End Patch`.
- Start each operation with `*** Add File: <path>`, `*** Delete File: <path>`, or `*** Update File: <path>`.
- An update may be followed by `*** Move to: <new path>` and contains one or more `@@` hunks.
- Hunk rows start with space for context, `-` for removal, or `+` for addition. Every added-file line starts with `+`.
- Use about three context lines around a change; add a copied `@@` class or function anchor when context alone is not unique.

## Examples
- `{"input":"*** Begin Patch\n*** Update File: x.txt\n@@\n-old\n+new\n*** End Patch\n"}` updates one file.
- `{"input":"*** Begin Patch\n*** Add File: notes.txt\n+hello\n*** Delete File: obsolete.txt\n*** End Patch\n"}` creates one file and then deletes another.
- `{"input":"*** Begin Patch\n*** Update File: old.go\n*** Move to: new.go\n@@\n-package old\n+package new\n*** End Patch\n"}` updates and moves a file.

## Recoverable failures
- Missing envelope or operation header: rebuild the patch with the required markers.
- Context not found or ambiguous: re-read the target and use current, more specific context.
- Invalid path: use a workspace-relative path; absolute and escaping paths are rejected.
- Any operation failure: inspect current files before constructing a new patch; do not assume partial intent succeeded.
- Multi-operation patches are applied in authored order; earlier operations may remain committed when a later operation fails.

## Anti-patterns
- WRONG: omit `+` prefixes in an added file. RIGHT: prefix every new-file line.
- WRONG: use absolute paths. RIGHT: use workspace-relative paths.
- WRONG: reuse stale context after a failed patch. RIGHT: re-read and construct a fresh patch.

<critical>
- Include the complete `*** Begin Patch` / `*** End Patch` envelope.
- Give every file operation an explicit action header.
- Never target a path outside the workspace.
</critical>
