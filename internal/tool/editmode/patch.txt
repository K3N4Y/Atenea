Patch existing files with anchored diff hunks, or explicitly create, delete, or rename a file. Use the smallest operation that completely expresses the intended change.

## Input grammar
- `path` is required and applies to every entry in `edits`.
- Each entry uses `op: "update"`, `op: "create"`, or `op: "delete"`, plus optional `rename` and `diff`.
- An update `diff` contains one or more hunks beginning with `@@` or `@@ $ANCHOR`; hunk lines begin with space, `+`, or `-`.
- A create `diff` is the complete new file content without prefixes. A delete has no `diff`.
- For update plus move, set `rename` to the new workspace-relative path.

## Examples
- `{"path":"x.txt","edits":[{"op":"update","diff":"@@\n-old\n+new"}]}` replaces a unique line.
- `{"path":"src/old.go","edits":[{"op":"update","rename":"src/new.go","diff":"@@ func Name()\n-func Old() {\n+func Name() {"}]}` updates and moves a file.
- `{"path":"notes.txt","edits":[{"op":"create","diff":"first line\n"}]}` creates a file explicitly.

## Recoverable failures
- `Found multiple matches`: add copied context, use a more specific `@@ $ANCHOR`, or split the change into separate hunks.
- `No match found`: re-read the file; the context may be wrong or stale.
- Invalid diff syntax: ensure every hunk starts with `@@` and every hunk row has a valid prefix.
- Failed or structurally broken edit: re-read current content and build a new patch; never retry the same diff unchanged.

## Anti-patterns
- WRONG: use generic anchors such as `import`, `function`, or `const`. RIGHT: copy a unique signature or literal from the file.
- WRONG: overwrite a whole file for a small change. RIGHT: patch the minimal unique region.
- WRONG: patch whitespace line by line. RIGHT: run the project formatter once after semantic edits.

<critical>
- Read the target file before editing.
- Copy anchors and context verbatim, including whitespace.
- Keep every addition inside the intended structural block.
</critical>
