Perform one content-addressed string replacement in a file with fuzzy whitespace matching. Use it when the old text itself uniquely identifies the edit.

## Input grammar
- `path`, `old_string`, and `new_string` are required.
- `old_string` must be the smallest text that uniquely identifies the target.
- Set `replace_all=true` only when every occurrence in the file must change.

## Examples
- `{"path":"config.go","old_string":"const retries = 2","new_string":"const retries = 3"}` replaces one unique occurrence.
- `{"path":"README.md","old_string":"OldName","new_string":"NewName","replace_all":true}` replaces every occurrence in one file.

## Recoverable failures
- `old_string` not found: re-read the file and copy current text.
- Multiple matches: add surrounding context or deliberately set `replace_all=true`.
- File not read in this conversation: read it, then retry with current content.
- No-op replacement: provide a `new_string` that differs from the matched text.

## Anti-patterns
- WRONG: use a broad `old_string` that happens to match today. RIGHT: use the smallest unique text.
- WRONG: set `replace_all=true` to avoid understanding multiple matches. RIGHT: use it only when all occurrences should change.
- WRONG: use string replacement for a structure-aware codemod. RIGHT: use `ast`.

<critical>
- Read the file before editing.
- Ensure the intended match set is unambiguous.
- Prefer editing an existing file over creating a duplicate.
</critical>
